The experiment

Not a speedrun, and not a prerecorded script

The game ran locally in PyBoy from a privately supplied Pokémon Red cartridge image. Copilot observed the same 160×144 frames as a viewer, described the situation, chose a short controller sequence, and repeated. The runtime checkpointed emulator state, persisted cartridge RAM, recorded bounded video clips, and published health telemetry while a supervisor recovered failed processes.

The first version treated every obstacle as a movement problem. That worked on routes and failed in the places that make Pokémon a game: item gates, one-time events, menus, switches, teleporters, boulders, and battles. The successful system became a hybrid. The model kept responsibility for perception and open-ended decisions; RAM supplied facts the screen could not reliably reveal; deterministic controllers replayed only routes that had been proven in disposable emulator copies.

What “autonomous” means here: the live agent played the game and recovered continuously, but the controller itself was improved when evidence exposed a new failure class. This was an autonomous run inside an active engineering loop—not a claim that one untouched prompt solved the game.

Where it broke

The failures were more useful than the victories

Topology could not explain semantic gates

A collision mapper can learn that a Snorlax or a locked Silph door is impassable. It cannot infer that the answer is the Poké Flute or Card Key. The run spent hundreds of decisions re-probing impossible edges until key-item ownership became explicit state and story guidance outranked generic exploration.

Teleporters made valid movement look like progress

Silph Co. exposed a closed two-pad cycle between 5F and 9F. Every transition was real, so a naive novelty metric rewarded the loop. Reading the live warp table and naming fixed destinations turned teleporters from “new movement” into a graph with detectable cycles.

Puzzles needed event state, not screenshots alone

Seafoam and Victory Road depended on boulder coordinates, switch flags, holes, currents, and one-way transitions. The controller began reading the same event bits the game uses, then searched disposable emulator states with breadth-first search. A route was promoted to trusted execution only after the destination map and coordinates were reproduced.

Long-running autonomy is an operations problem

The gameplay process once remained dead for 6.3 days after transient authentication failures exhausted a restart circuit. Other incidents included stale stop-command replay, configuration drift on bare restarts, an independent manual driver repeatedly stealing control, and stream processes outliving the player. Durable desired-state replay, cooldown-and-retry supervision, health events, and strict AI ownership mattered as much as game reasoning.

Menus are state machines too

The final Cerulean Cave route was emulator-proven, but the first Surf macro opened the Pokédex because the START cursor had moved. The fix did not add more blind buttons. It read the cursor, verified each menu screen, selected Pokémon, selected Blastoise, selected Surf, and resumed the coordinate route only after RAM confirmed the surfing state.

The final capture

Safety constraints became executable

Mewtwo was too important to leave to a probabilistic battle choice. The controller stood at (27,14), verified the static opponent’s internal species ID, refused the FIGHT branch, opened the item menu, scrolled to the Master Ball’s observed bag slot, and used it. Ordinary cave encounters used a separate RUN controller, and the Mewtwo tile was explicitly excluded from that behavior.

Success was not inferred from dialogue. The definitive assertion was Pokédex ownership bit 150. When that bit changed, the runtime created a checkpoint and paused before any further action could endanger the result.

What we learned

Principles for agents that must keep going

  1. Separate observation from truth. Screens explain context; machine-readable state proves irreversible facts.
  2. Escalate by failure class. Repeated movement cannot solve an item gate, and repeated prompting cannot repair a dead supervisor.
  3. Make routes falsifiable. Store expected map/coordinate transitions and abort on any surprise.
  4. Preserve ownership. Operator tools must not silently switch an autonomous controller into manual mode.
  5. Persist desired state, not just process state. A restart is only recovery if model, flags, save, and control mode return unchanged.
  6. Turn safety language into code. “Never attack Mewtwo” became a battle-menu invariant rather than a hopeful prompt.
  7. Keep the evidence. Hash-checked checkpoints, event receipts, and a sanitized timeline made the result auditable.

Reproduce responsibly

The code is public; game content is not

The repository contains the agent, tests, supervisor, viewer, streaming system, and public-safe story tooling. It does not contain or distribute a ROM. Saves, screenshots, raw decisions, credentials, and the final cartridge-linked archive remain local and private.
